# 每日岛屿 · MVP

可直接托管的原生 HTML / CSS / JavaScript 网站，无构建依赖。项目包含 Web App Manifest、灯塔图标和基础离线缓存。

## 运行与检查

- 在普通本地开发环境中，可用任意静态文件服务器打开 `dist/`。
- `npm test`：检查任务规则、连通土地、持久化、跨日、历史补录与界面事件主流程。
- 主要入口为 `dist/index.html`，数据规则在 `dist/model.js`，统一主题和建筑绘制在 `dist/scene.js`。

## 第一版范围

每天恰好一个 S 才可开始；A/B/C/F 为可选任务。规划时不展示主题，开始时揭晓并锁定海风庭院。土地、起点小屋、S 灯塔、A 书屋及其余庭院景观使用同一主题定义。一个完成任务对应一块永久固定的邻接土地。完成 S 前角色停在起点；此后支持路径移动和轻度漫游。可以结算、跨日保存和补录历史已有任务。没有城市扩张、升级、商店、多 S 和实际云同步。

## 数据与验证限制

存档位于当前浏览器的 localStorage；刷新可恢复，更换浏览器或设备不会同步。历史补录默认明确保留“实际时间未知”，另存补录时间，也可确认具体时间。无法读取的存档不会被覆盖。

## 账户准备与未来同步

右上角的「账户」窗口提供用户名和密码的登录、注册入口。当前未连接认证服务，提交后显示「待传输」，不会创建账号、验证身份或上传数据。密码只用于当次表单处理，当前实现会立即清除，不写入岛屿存档或其他本地存储；接通服务后需要重新填写。访客可以继续使用全部功能，岛屿数据仍首先保存到 `daily-island-v1` 这份本地存档。

`dist/account-backend.js` 是待接入的认证与同步适配器，定义 `restoreSession`、`signIn`、`signUp` 和 `syncLocal`。只有适配器返回带真实用户 ID 的已验证 session，页面才会尝试传输本地快照；每次本地保存仍独立成功。接入时还需配置实际 Supabase 项目、用户表/访问策略和新旧记录合并规则。Supabase Auth 的标准密码方式使用邮箱或手机号；如果继续用纯用户名登录，需要额外实现安全的用户名映射或认证服务，不能仅填入项目 URL 和密钥就启用。

已在桌面浏览器确认 GitHub Pages 首页可以打开；未对手机触屏和断网状态进行真机验证。自动化覆盖数据规则及界面事件流程，不替代真机布局验证。

## 托管

GitHub Pages 通过 `.github/workflows/deploy.yml` 自动测试、构建并发布 `build/`。推送到 `main` 后会自动更新网站。项目资源和 PWA 作用范围使用相对路径，可部署在仓库子路径下。
